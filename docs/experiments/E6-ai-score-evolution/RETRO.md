# E6 — AiScoreProvider 진화 실험 회고

> **Status**: 실험 미실행 시점의 회고. 실측이 들어오면 갱신.
> 코드 들이고 측정 안 한 상태에서의 인정과 후속 자리만 적는다.

---

## 1. 실험 없이 코드 들인 게 ADR-011 의 약점이다

Phase 4 에서 두 어댑터 (Heuristic / Statistical) 를 들였다.
들이는 시점에 다음 셋이 다 직관이었다.

- Heuristic 의 가중치 (0.4 / 0.25 / 0.1 / 0.2 / 0.3 / 0.15).
- 두 어댑터의 sigmoid scale (`* 4`, `(z - 2.0) * 1.5`).
- 두 어댑터 중 default 를 Heuristic 으로 잡은 결정.

ADR-009 가 "직관/관습이 아닌 데이터가 결정의 근거" 라고 말하고 있는데, Phase 4 의 코드는 그 규칙을 정직하게 어긴 자리다.
E6 가 그걸 메우러 가는 실험인데, 그 실험조차도 라벨 부재로 "분포만 본다" 가 한계다.

여기서 인정할 게 있다.
**E6 를 돌리지 않은 상태에서 ADR-011 이 만들어진다면, 그 ADR 은 직관으로 채워진 결정의 사후 합리화에 가깝다.**
ADR-011 을 합리적으로 쓰려면 적어도 H1 / H2 / H3 의 실측 결과가 ADR 안에 인용되어야 한다.

---

## 2. 가설 H4 의 의미

H4 는 "라벨 부재로 정밀도/재현율 측정 불가" 라고 박았다.
이게 negative finding 의 자리다. 실험을 안 해도 결론이 나와 있는 가설.

이걸 가설로 박은 이유는 **다음 사람이 E6 결과를 보고 "분포가 좋으니 어댑터가 정확하다" 라고 오해하지 않게** 하기 위해서다.
분포가 의도대로 형성된다는 건 어댑터의 출력이 합리적이라는 약한 신호일 뿐, 그 출력이 실제 fraud 와 일치한다는 강한 신호는 아니다. 둘은 다른 자리다.

---

## 3. 후속 실험 E6-1 — 라벨 수집 후 정밀도/재현율

E6 가 H4 의 한계를 인정하고 끝난다면, E6-1 은 그 한계를 푸는 자리다.

전제 조건.
- 운영자 검토 UI 가 있어야 한다. RiskLog 한 건을 사람이 보고 "진짜 fraud / 오탐" 을 박는 자리.
- 데이터 스키마에 `is_fraud_human_labeled: boolean?` 컬럼 추가 (또는 별도 `risk_log_labels` 테이블).
- 라벨 최소 1000건 축적. 그 미만에서는 confusion matrix 의 통계적 의미가 약하다.

E6-1 의 가설 후보.
- L1: Heuristic score >= 0.7 자리의 정밀도가 0.3 이상.
- L2: Statistical score >= 0.7 자리의 정밀도가 0.4 이상 (사용자 패턴 본다는 가정 아래).
- L3: 두 score 의 OR 결합 (max) 또는 weighted average 가 단일 어댑터보다 정밀도가 높다.

E6-1 은 Phase 5 이후의 자리.
Phase 5 에서 운영자 검토 인터페이스를 들이고, 라벨이 쌓이는 동안 다른 작업 (예: Isolation Forest PoC) 을 진행한 뒤 E6-1 을 돌리는 흐름.

---

## 4. 후속 실험 E7 — dense_vector kNN

E7 은 다른 결의 후속이다. 라벨 없이도 시작할 수 있는 자리.

설계는 `docs/etc/ml-anomaly-detection-poc.md` 에 잡혀 있다. 거래를 벡터화하고 Elasticsearch dense_vector + kNN 으로 "이 거래와 가장 가까운 과거 거래 N 건" 을 찾는 접근.
fraud 라벨이 붙은 과거 거래와 가까운 거래에 가산점을 주는 방식이라, 일부 라벨만 있어도 의미를 가진다.

E6 가 분포만 보는 데 비해, E7 은 "거래 간 유사도" 라는 새 변수를 도입하는 자리. Heuristic / Statistical 과 보완 관계.

---

## 5. 회고 — 측정 없이 코드 들인 패턴

Phase 4 에서 한 일을 정직하게 적으면 이런 순서다.

1. AiScoreProvider 의 빈 슬롯이 너무 오래 있다고 느낌.
2. 외부 ML 은 학습 데이터 / latency / 비용 셋이 다 막혔다고 판단.
3. Heuristic 부터 들임. 가중치는 직관.
4. Statistical 도 들임. cold start 정책은 직관.
5. 메트릭만 박고 측정은 미룸.

이 순서에서 **측정이 코드 들이는 일보다 늦어진 자리** 가 보인다.
ADR-009 의 규칙은 "측정이 결정보다 먼저" 인데, 여기서는 코드가 측정보다 먼저였다.

다음 라운드에서는 이 순서를 뒤집어야 한다.
- 어댑터 후보를 정한다.
- 측정 가능한 지표를 먼저 정의한다 (분포 / 처리량 / 라벨 정밀도).
- 측정 인프라 (k6 시나리오 + 라벨링 UI) 를 먼저 들인다.
- 그 위에서 어댑터를 들이고 즉시 측정한다.

이 흐름이 익숙해지면 Phase 4 의 약점이 반복되지 않는 자리.

---

## 6. 남은 인정 두 개

**(1) E6 가 NOT YET RUN 인 채로 phase-4 회고가 공개되면, 회고의 정직성은 보존되지만 ADR-011 의 근거는 비어 있다.**
회고는 "측정 안 했다" 를 인정할 수 있지만, ADR 은 결정의 근거를 적는 자리라 인정만으로 채워지지 않는다.
이 갭은 E6 실행으로만 메워진다.

**(2) "분포만 본다" 가 정직한 자리이긴 한데, 동시에 회피로 보일 수도 있다.**
라벨 수집은 운영 자원이 드는 일이고, 사이드 프로젝트 규모에서 그걸 미루는 건 합리적이긴 하다.
다만 그 미룸이 "측정 어렵다 = 측정 안 한다" 로 굳어지면 ADR-009 가 무의미해진다.
E6-1 을 후속 자리로 박아두는 게 그 굳음을 막는 약속이다.
