# TDD Loop Skill

## 1️⃣ Red (실패하는 테스트 작성)

### 질문
- 이 기능의 핵심 행위는?
- 성공 케이스는?
- 실패/예외 케이스는?
- 경계값은?

### 규칙
- 테스트 먼저, 구현 없이 작성
- 컴파일 에러 허용 (클래스/메서드 없어도 됨)
- 테스트명은 행위 기반 한글로
- Arrange-Act-Assert 구조

### 출력
```kotlin
@Test
fun `[행위] - [조건] - [결과]`() {
    // arrange
    // act
    // assert
}
```

---

## 2️⃣ Green (최소한으로 통과)

### 규칙
- 테스트 통과만 목표
- 하드코딩 허용
- 설계 고민 금지
- 리팩토링 금지

### 질문
- 테스트가 통과하는 가장 단순한 구현은?

---

## 3️⃣ Refactor (구조 개선)

### 체크리스트
- [ ] 중복 제거
- [ ] 네이밍 개선
- [ ] 책임 분리
- [ ] 매직 넘버 상수화
- [ ] 테스트도 리팩토링

### 규칙
- 테스트 통과 상태 유지
- 한 번에 하나만 변경
- 변경 후 즉시 테스트 실행

---

## 4️⃣ 반복 조건

다음 조건 만족 시 다음 기능으로:
- 모든 케이스 커버됨
- 코드 가독성 확보
- 테스트가 문서 역할 수행

---

## 5️⃣ 안티 패턴

❌ 구현 먼저 → 테스트 나중
❌ 한 번에 여러 기능 구현
❌ Green에서 설계 고민
❌ Refactor 없이 다음 기능
❌ 테스트명이 구현 세부사항

---

## 6️⃣ 예시 흐름

```
[Red] 유효한 이메일이면 Email 객체 생성
  ↓ 실패
[Green] 하드코딩으로 통과
  ↓ 통과
[Refactor] 정규식 추출, 상수화
  ↓ 통과
[Red] 잘못된 이메일이면 예외
  ↓ 반복
```
